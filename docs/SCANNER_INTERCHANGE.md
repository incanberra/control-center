# Scanner interchange and collection status

The Collection and scanners screen is available at `/?tab=collection`. Reading status and report previews is local and does not start collection or AI work. The existing scheduler runs while the application process is alive; no OS task or always-on service is installed. Automatic collection and optional import controls are persisted in SQLite. Automatic imports start off.

## Version 1 export

```json
{
  "version": 1,
  "producer": "geoeconomics",
  "run": {
    "id": "producer-stable-run-id",
    "title": "Producer report title",
    "edition": "morning",
    "generatedAt": "2026-10-06T05:15:00+11:00",
    "windowStart": "2026-10-05T03:00:00+11:00",
    "windowEnd": "2026-10-06T03:00:00+11:00",
    "status": "complete",
    "warnings": [],
    "briefMarkdown": "# Saved report\nProducer text"
  },
  "items": [{
    "id": "producer-stable-event-id",
    "title": "Example fixture development",
    "summary": "Existing producer summary, not regenerated by Control Centre.",
    "publishedAt": "2026-10-05T14:00:00+11:00",
    "sources": [{ "name": "Original publisher", "url": "https://example.org/report" }],
    "kind": "news",
    "topics": ["Economic security"],
    "importance": 85,
    "stage": "main"
  }]
}
```

Supported producers: `geoeconomics`, `think-tanks`. Editions: `morning`, `ad-hoc`. Status: `complete`, `partial`, `failed`; failed runs cannot import reading items. Item kinds: `news`, `event`, `podcast`; stages: `main`, `annex`. Publication and window timestamps can be null if unverified; generation time must be valid and not in the future. Dates include timezone offsets and are normalized to UTC. Unknown publication dates are never replaced with the generation date. Importance is a producer score from 0 to 100, not an independent factual-confidence claim.

Limits: 500 items; 20 source links per item; 24 topics per item; title 1,000 characters; summary 12,000 characters; saved brief 512,000 characters. API/upload limit: 4 MB. HTTP/HTTPS source links must have no embedded credentials. Original source links are displayed but never fetched on import. The reader renders saved Markdown as safe React text, links and tables; producer HTML is not executed.

## Read-only adapters

The geoeconomics folder defaults to the parent workspace's `profiles/geoeconomics`. The adapter selects the latest dated morning Markdown, joins the same run in `monitor.db` opened read-only, and matches the generated clock against collection metadata. Summary text comes from the producer's stored stories. Publication dates come from classified source evidence. Missing or ambiguous evidence is rejected. An explicit dated ad-hoc run can be previewed/imported through the API but is never selected as the morning edition.

The Think Tank folder defaults to the known local scanner location and can be edited in the UI. `reports/latest.json` supplies only the run ID; its absolute directory/manifest paths are ignored. The adapter reads `reports/runs/<run-id>/run.json` and the same dated JSON/Markdown. Run and report identities must match. Incomplete/failed manifests are rejected. Source failures are labeled as partial coverage, with source names and backlog warnings retained. All accessed files must resolve beneath the configured folder; symlinks cannot point outside it.

Adapters do not modify either producer, read their `.env` files, launch scans or send email. Reports can also be exported through the viewer and manually uploaded to another local installation.

## Persistence and reading state

Schema 11 adds scanner connections, run revisions, source identities and run-item provenance, plus collection run history and controls. Imports validate the entire report before a single transaction. Reimporting identical content is a no-op. Changed valid reports update the stored run and matching evidence, while review/save/archive/feedback records remain separate. Older imported evidence cannot overwrite a newer imported version. Failed/malformed input and a partial revision of a complete run leave the complete run intact.

The most recent complete morning run per producer defines current scanner candidates. If none exists, the latest partial morning is used with its coverage label. Ad-hoc runs and older evidence remain searchable through Monitor History/Unreviewed and import history. A complete empty run advances the current edition but deletes no evidence. Producer source URLs and stable identities prevent duplicates; this does not perform semantic event clustering across unrelated URLs. Overlapping sources retain attribution without being counted as independent corroboration.

Imported candidates reuse producer priorities within the configured Monitor reading target. Overflow stays in History/Unreviewed. Imports neither invalidate collector snapshots nor trigger AI preference/summary work. Preferences continue to guide normal Monitor collection separately. Today reads the combined saved Monitor queue without recollection.

## Status meaning and recovery

Collection records distinguish started, complete, partial, failed and disabled checks; an unfinished record from a previous app session is labeled interrupted. Full success dates are preserved after errors. Newsletter backlog is the last measured count and is shown as unmeasured until available. Legacy saved snapshot times are labeled separately and are not invented full-success dates. Seven-day costs come only from this app's recorded OpenRouter ledger; unknown charges and external scanner costs are not represented as zero.

Complete backup/recovery includes all these tables and stored report text. Existing schema-10 data receives a consistent pre-migration backup before upgrade. Source reports remain in their authoritative scanner folders; the app backup contains only imported copies, not the entire scanner installations. Use the existing full backup command before upgrades and keep private backups outside GitHub.
